# 批量归档聊天

批量归档帮助你整理本机 Codex 聊天。侧栏中的“批量归档”按需打开选择面板；你可以按标题筛选、跨多次筛选累积选择，再核对完整范围后提交。

这份说明适用于 [0.3.0-preview.6](https://github.com/Mastery-L99/codex-nested-conversations/releases/tag/v0.3.0-preview.6)。侧栏入口和插件页面使用同一个归档服务。聊天可以保留在折叠的分支里，归档时无需逐个打开侧栏行或切换当前聊天。

## 选择聊天

工具栏通过当前桌面窗口归档，因此可以处理这个窗口持有的空闲聊天。如果聊天或后台子任务还在执行，工具栏会在提交前停止。独立插件页面使用单独的官方服务，遇到其他进程持有聊天时会说明原因。两种入口都会回读归档结果，失败后停止后续提交。

列表按聊天来源区分桌面对话和非交互式执行记录。由 `codex exec` 产生的测速、脚本等运行记录不进入目录或归档范围。真正的桌面聊天即使还没有标题，也会显示为“未命名聊天”，并附创建时间和短标识。

1. 在已加载增强的 Codex 窗口侧栏点击**批量归档**。
2. 展开主聊天查看子聊天。选中行会高亮，方框内出现勾号。按标题筛选时，匹配聊天的上级会一同显示，方便识别所属任务。**全选当前筛选**和**反选当前筛选**只处理真实匹配项，切换筛选后仍保留之前的选择。
3. **清空选择**会清除所有已选聊天，包括当前筛选下隐藏的项目。选择面板中的**取消**或**关闭**会退出并清空本次选择，不提交归档。
4. 默认勾选“同时归档所选主对话的全部下级”。范围依据增强已经发现的关系，包含已发现但在侧栏折叠的下级；没有发现的关系不会自动加入。取消勾选后，仅处理明确选中的聊天。
5. 点击**归档所选**进入第二个确认窗口。检查列出的聊天和去重后的总数；同一个聊天即使被多次覆盖，也只计一次。选择窗口中的数量是直接勾选数，确认窗口中的数量可能因加入下级而增加。

确认页分别列出聊天和后台子任务。例如，选中 4 个聊天、另有 12 个下级随上级归档，聊天清单就是 16 个。若其中有聊天派过智能体任务，第二份清单会列出官方归档会连带处理的后台子任务，并注明它们所属的聊天。同一子任务只计一次。

“包含下级”控制聊天树中的子聊天。即使关闭它，官方程序仍可能在归档聊天时处理其后台子任务。查看两份清单后再确认。聊天与后台子任务合计最多 256 条。执行时会复查范围，进度分别显示两类记录的归档结果。

## 确认、停止和恢复

确认窗口中选择**取消**会关闭确认窗口，再次打开面板可继续检查保留的选择。选择**归档全部**后，服务会重新读取本机聊天关系。确认期间若有新下级、改名或聊天移出范围，会提示重新核对。范围一致时，服务按确认清单调用官方归档接口，逐项读取归档结果。已选范围内的下级先于对应主聊天处理。

执行中可以点击**停止后续操作**。已经提交的当前项可能仍在完成，已完成的归档不会自动撤销；尚未提交的后续聊天保持原样。遇到错误或无法确认结果时，程序停止后续操作。请在原应用中检查已经归档的聊天和当前项的状态，再决定是否对剩余聊天重新操作。

归档用于整理侧栏，聊天不会因此被删除。需要恢复时，在原应用的设置中查看**已归档聊天**，找到目标聊天并使用界面提供的取消归档或恢复入口；具体入口和名称取决于官方客户端版本，此工作流仍需在目标版本实机确认。批量归档面板没有批量撤销功能，也没有批量删除功能。

## 范围与启动

面板只列出当前可识别、尚未归档的本机 Codex 聊天；云端 ChatGPT 聊天、远程主机和其他账号不属于操作范围。它依靠当前发现的聊天与层级信息，列表或关系发生变化时，应重新查看选择和确认范围。

开机自启动保持关闭。通过原图标自动加载增强是单独的工作，仍在验证；请按当前安装版本的启动说明使用。此功能不会修改官方应用的更新方式，也不能保证无需适配未来的官方版本。
