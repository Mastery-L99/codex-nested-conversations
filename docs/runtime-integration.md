# 运行模块整合约定

0.3.0-preview.6 将嵌套显示与批量归档放在同一项目中，分别加载、分别启停。共享设置和关系信息用于协同，归档执行路径独立于侧栏适配器。独立开关和停止伴随模块后的归档通路均已实机检查；安装后的插件在正式宿主完成了专用单项归档的页面、提交和结果闭环。多级与故障场景按各自的测试范围记录。本文件同时保留各模块的实现与后续验收约定。

## 模块边界

| 模块 | 入口与职责 | 不依赖的组件 |
| --- | --- | --- |
| 独立归档 | `archive-server.cjs` 提供 MCP 工具和页面资源；`archive-core.cjs` 管理范围、顺序与执行；`archive-app-server.cjs` 调用官方程序 | 侧栏 DOM、调试端点、Playwright、Windhawk、原列表运行进程 |
| 独立嵌套目录 | `open_nested_chats` 注册官方插件全屏和聊天旁入口，两种视图共用预构建的 SDK 页面。展开或刷新只读取目录，点击具体聊天时向官方包发送打开请求 | 原侧栏适配器、调试端点、Playwright、Windows 自启动 |
| 原列表增强 | `runtime-main.cjs` 连接当前官方窗口；`ui-modules.js` 分别安装嵌套、原列表归档和事件组件 | 独立归档页面是否打开 |
| 共用设置 | `module-state.cjs` 保存两个开关；`windows-mutex.cjs` 协调本项目并发操作 | 官方数据库写入、Windows 常驻服务 |

嵌套关闭时，原列表模块仍可保留识别聊天和打开原生菜单所需的桥接。归档关闭时，移除增强归档控件并停止后续提交，嵌套开关不变。一个组件的加载、检查或释放失败，需要记录该组件的错误并继续初始化其他组件。原列表依赖失效时，独立页面仍有自己的服务通路。

上述归档只支持符合条件的本机 Codex 聊天。原列表可以在 Codex、ChatGPT 两种模式显示这些聊天，不能据此扩大为云端 ChatGPT 归档支持。子聊天关系与 subagent 执行关系分别处理。

## 分发目录与依赖

- `runtime-manifest.json.files` 列出完整运行包允许复制的源码；`archiveFiles` 是独立插件需要的子集。增加依赖时同步相应清单。
- 安装器将运行源码复制到 `app/`，公开 Playwright 依赖放在本项目的 `node_modules/`。禁止借用官方安装中的内部依赖。
- 安装器另行准备干净的 `plugin/`，安装根目录的 `.agents/plugins/marketplace.json` 只指向该子目录，避免宿主把完整开发或安装目录复制进插件缓存。
- `npm run build:plugin -- --output-dir <新目录>` 生成插件本体：插件元数据、`archiveFiles` 及相应许可说明；它不生成 marketplace 目录，不登记插件，不启动官方应用。
- 完整源码包、完整安装目录、独立插件目录是不同的制品。源码发布与官方公共插件目录上架也分别办理。
- 独立归档服务使用 Node.js 内置模块、Python 标准库及 Windows PowerShell。预构建 `archive-panel.html` 自带页面 SDK，运行时不从远程加载页面依赖。修改页面后应重新构建并保留第三方许可证。

只允许复制清单内的普通文件，禁止路径跳转和重解析点。源码和插件包不能包含官方应用资源、账户资料、会话、运行日志、个人偏好或依赖缓存。

## 路径与设置

- `CNCC_DATA_DIR` 指定模块工作数据目录。关系缓存、运行状态、停止请求、偏好、日志和独立归档任务记录写入项目数据位置。
- `CNCC_SETTINGS_DIR` 指定两个模块共用的设置目录。完整安装为两个入口传入同一位置；未指定时，默认设置位置为 `%USERPROFILE%\.codex-nested-conversations\settings`。
- 两个开关保存在 `module-state.json`，更新时在同名互斥锁内读取最新状态、合并单独字段、递增版本并替换文件。关闭其中一个不能覆盖另一个的值。损坏状态不能静默写回默认值并恢复归档执行。
- `CNCC_NODE`、`CNCC_PYTHON` 为安装时检测到的可执行文件绝对路径。独立源码插件使用宿主继承的 PATH，可通过 `CNCC_PYTHON` 指定解释器。
- 源文件通过 `__dirname` 或 `$PSScriptRoot` 定位，不能把源码目录当成运行数据目录。用用户环境和官方包发现机制定位安装，不硬编码开发者路径。
- Start、Stop 包装脚本在结束或失败时还原调用者的 `CNCC_*` 环境变量，防止临时数据目录传入后续操作。

## 独立归档流程

原窗口工具栏和独立页面共用范围确认、后台子任务清单和归档回读。工具栏绑定当前官方本机窗口，只能按本地聊天 ID 发送读取元数据和归档两种请求，并按请求 ID 匹配回复。它可释放同一宿主持有的空闲聊天。独立页面继续使用自己的官方子进程。连接失败时不会把已发送的请求换到另一路径重试。

`archive-catalog.py` 只读获取符合条件的聊天元数据，平面目录不依赖嵌套读取器。关系库、关系适配器缺失或损坏时返回平面目录，并说明无法读取层级；页面必须要求用户主动取消“包含下级”，才能只归档勾选项。不得自动缩小用户选择的范围。

页面展示完整范围后，服务保存有期限的一次性计划，确认只提交对应计划标识。执行前重新读取目录和关系，范围变化时停止并要求重新检查。执行串行进行，逐项检查真实归档状态，失败后停止后续提交；不能把接口 ACK 当成存储完成。

实际操作通过发现的官方 `codex app-server` 完成，不直接写 SQLite。适配器只启动和管理自己的子进程，不结束官方桌面主进程。状态读取不请求聊天正文或启动模型轮次。

官方归档可能连带后台子任务，接口没有提供原子化的确认范围条件。调用前检查隐式下级是否都在确认范围内；提交后的未知影响应如实反馈。并发创建下级仍存在时间窗口，界面必须说明这个边界。停止阻止后续提交，不能撤销已完成或已提交的请求。

独立任务写入项目自己的记录。服务重启后，不能自动重试状态不确定的归档；将中断状态交给用户检查。服务关闭时释放自己持有的连接、监听和子进程，不关闭官方窗口。

## 原列表的启动与停止

- `Start-NestedConversations.ps1 -CheckOnly` 只检查，不启动应用、不改入口、不写个人数据。
- 原列表适配器只连接已发现的官方安装及其主进程，临时调试端点必须绑定回环地址。所有者或地址不匹配时停止。
- 官方应用以普通方式运行且没有可用连接时，提示正常退出后重开；不强制结束应用，不创建另一份 profile。
- 原列表的归档入口保留原生菜单，并在具备准确身份和范围检查时接入 `Ctrl+Shift+A`。停止时解绑增强处理；不增加备用全局组合键。
- 关系更新采用原生事件和文件变化补充触发，不设置固定 20 秒空闲全量扫描。独立页面可在任务运行期间查询进度，空闲时不持续查询目录。
- `Stop-NestedConversations.ps1` 只停止原列表伴随进程，移除其样式、监听、菜单、隐藏行和全局绑定，读取本次请求对应的恢复结果。成功状态为 `stopped_ui_restored`；恢复不完整返回失败，不能只依据进程退出宣称成功。
- 禁止调用 `browser.close()` 关闭官方应用。停止原列表模块也不能顺带禁用独立归档插件。

直接点击原官方图标自动加载嵌套仍是单独的加载工作。Windhawk 当前只是未安装原型，编译或离线测试不能代表冷启动通过。项目保持 GPT 的 Windows 开机自启动关闭，不安装后台加载服务。

## 验收门槛

文件复制成功、CLI 安装成功、页面资源可读分别只代表对应步骤。声称完整功能可用前，需要在目标桌面宿主检查页面、工具桥接、开关独立性、确认范围、真实测试聊天的提交结果，以及停止和卸载恢复。官方版本变化后重复相关检查。
